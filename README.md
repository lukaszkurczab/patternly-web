# Patternly Web

## Product boundary

The hosted site is a marketing brochure for the Patternly mobile app. It contains a bounded interactive SQL example, the practice method, and a track catalogue. It does not provide sign-in, account or learning state, purchases, privacy or data-rights intake, private responses, or administrator access. User data-rights requests start in the mobile app under Settings.

The administrator panel is a local Product Owner tool. It runs on loopback with the local backend and Firebase Auth/Firestore emulators. Firebase Authentication and backend administrator authorization protect its operations. It is not built into `dist` or deployed to Firebase Hosting.

The public catalogue contains all nine canonical release tracks, including independent Claude Architect Professional practice. It does not claim Anthropic affiliation.

## Public site

Requirements: Node.js 20.19 or newer. Run `npm install`, then `npm run dev` to see the page at `http://localhost:5173/`. Local dev uses a temporary, test-only legal artifact generated by the app's synthetic artifact builder. `src/main.jsx` is the public entry. Vite builds the marketing page plus `privacy.html` and `terms.html` as MPA entries. Firebase Hosting's `cleanUrls` exposes the latter as `/privacy` and `/terms`.

Production `npm run build` requires `PATTERNLY_PUBLIC_LEGAL_ARTIFACT_PATH` and `PATTERNLY_PUBLIC_LEGAL_EXPECTED_FINGERPRINT`. The artifact must match schema `patternly-public-legal-export-v1`, contain release data, and match the independent fingerprint from readiness. The build rejects missing or malformed artifacts, a mismatched fingerprint, and any `testOnly` artifact. Set both variables from the legal export and readiness output before running the build.

Run `npm run verify:local` for a local-test build and checks of the actual app-produced synthetic artifact, marketing and legal page renders with legacy EN/PL and synthetic seven-locale content, the local admin entry, and negative direct requests for `/admin` and `/privacy-request` in the public preview. This synthetic artifact is generated in a temporary directory and does not prove readiness with production legal values. `firebase.json` publishes only `dist` and provides no admin or privacy-request route rewrites. This local check does not prove what is currently deployed to a remote Firebase Hosting site.

If the mobile app producer emits all seven supported locales, public legal pages expose a locale only when its document version, both profile records and both legal document strings are complete. EN/PL remain required by schema v1, so older artifacts continue to render with those two options. To cross-check the explicitly supplied seven-locale test artifact from the app producer and its separately obtained fingerprint, set `PATTERNLY_PUBLIC_LEGAL_ARTIFACT_PATH` and `PATTERNLY_PUBLIC_LEGAL_EXPECTED_FINGERPRINT` and run `npm run test:public-legal:producer`. This hook uses the dedicated `contract-test` mode, has no synthetic-fixture fallback, and also confirms that production rejects the same `testOnly` artifact.

The public page's interactive example does not save progress or schedule reviews. Manrope and IBM Plex Sans are bundled locally. Track SVGs come from the mobile app icon mapping. The page does not offer a purchase action.

## Local administrator workspace

From `../patternly-backend`, run `npm run dev:admin`, then open `http://127.0.0.1:25173/admin`. The launcher starts the local API and Firebase emulators and supplies web configuration. Credentials and persistent local data are described in `../patternly-backend/docs/local-admin.md`. No cloud account is needed.

`admin.html` loads `src/adminMain.jsx` only in Vite development. `/admin/` and `/admin.html` redirect to local `/admin`. The administrator entry has static `noindex,nofollow` metadata as an extra local precaution. The production preview and Firebase Hosting have no admin route. The local panel provides overview, question search and inspection, usage counts, report triage, privacy and legal request queues, and security incident operations through the backend.

`VITE_ADMIN_AUTH_EMULATOR_ORIGIN` explicitly selects the local SDK connection. It is accepted only in Vite development on a loopback browser host, with HTTP loopback API and emulator origins and project `demo-patternly-admin`. Restart the dev server after changing Firebase environments. Public builds do not include admin configuration.

Run `npm run test:admin-config` for configuration checks. `npm run test:admin-behavior` uses Playwright and an isolated local Vite server to exercise session races, access denial, status changes and uncertain writes; use `ADMIN_BROWSER_EXECUTABLE` when an installed Chrome is available. With the local stack running, `npm run test:admin-local` checks real emulator login, queue and question reads, usage statistics, and logout without changing reports.

The backend owns publication configuration and administrator authorization. Question statistics refer to the backend-selected immutable publication; usage counts describe stored synchronized records and are not active-user analytics. Admin-specific styles are in `admin.css`.

## Hosting

The configured Firebase Hosting site is `patternly-app-sandbox`. A deployment publishes only the verified `dist` directory. Deployment requires its own approval and remote verification; a local build does not establish what the hosted site serves.
